[ ] 7. CUSTOMER RETAIL SALES LOGGING & PROFIT TESTING (CUSTOMER TESTING FLOW)
    
    This feature is designed for distributors who sell physical stock directly to retail 
    customers (non-distributors) at the retail/customer price. The distributor collects
    the money directly from the customer, then logs the sale in the app to:
    a) Earn the "Retail Profit" (Customer Price - Distributor Price) directly credited to their wallet.
    b) Accumulate Personal Volume (PV) from the customer purchase, which boosts their PPV.
    
    Since this is a transaction-heavy backend service, test it using the automated scripts
    and by checking the database tables and endpoints. Follow this step-by-step checklist:

    [ ] 7.1. Run the Automated Customer Sales Test Script:
             [ ] Open a terminal in the project root.
             [ ] Run: npm -w api run test:customer-sales
             [ ] Wait for the execution.
             [ ] Verify that all 6 verification stages pass:
                 - Logging in as admin and creating a test seller (BF-TZ-99999) if not exists.
                 - Creating/updating a test product with:
                   * Customer Price = 100,000
                   * Distributor Price = 80,000
                   * Product PV = 50
                 - Logging a customer sale of 2 units via POST /api/customer-sales.
                 - Verifying that a commission row of type "retail_profit" is created with amount = 40,000.
                 - Verifying that GET /api/customer-sales returns the sale in the history.
                 - Verifying that GET /api/ranks/me includes the 100 PV (2 units * 50 PV) in the distributor's personalPV.
             
    [ ] 7.2. Manual API testing (via Postman / cURL):
             [ ] Log in as a distributor and obtain the Bearer Token.
             [ ] Send a POST request to: http://localhost:3001/api/customer-sales
                 Headers:
                   Content-Type: application/json
                   Authorization: Bearer <DISTRIBUTOR_TOKEN>
                 Body:
                   {
                     "customerName": "John Customer",
                     "customerPhone": "+255799988877",
                     "countryId": "<COUNTRY_UUID>",
                     "items": [
                       { "productId": "<PRODUCT_UUID>", "quantity": 1 }
                     ]
                   }
             [ ] Verify the response status is 201 Created and returns the logged sale ID, totalAmount, and totalPV.

    [ ] 7.3. Database Ledger Verification (Supabase Dashboard):
             [ ] Open your Supabase project dashboard.
             [ ] View the `customer_sales` table. Verify a row exists with:
                 - distributor_id: matching your test distributor UUID.
                 - customer_name: "John Customer".
                 - total_amount: equal to the Customer/Retail price of the product.
                 - total_pv: equal to the PV of the product.
             [ ] View the `customer_sale_items` table. Verify a row exists linking to the customer sale with unit_customer_price, unit_distributor_price, and quantity.
             [ ] View the `commissions` table. Verify a row exists with:
                 - beneficiary_id: your distributor UUID.
                 - type: "retail_profit".
                 - amount: (unit_customer_price - unit_distributor_price) * quantity.
                 - source_id: the ID of the customer sale.
                 - source_type: "customer_sale".
             [ ] View the `wallets` table. Verify that the distributor's wallet balance has increased by the retail profit amount.
             [ ] View the `wallet_transactions` table. Verify that a transaction ledger row has been created with:
                 - type: "credit".
                 - source_type: "commission".
                 - source_id: the ID of the commission row.
                 - amount: the retail profit amount.
                 - balance_after: the updated wallet balance.

    [ ] 7.4. Distributor App Progress Verification:
             [ ] Log in as the distributor in the mobile app.
             [ ] Go to the Account tab.
             [ ] Verify that the Wallet balance (displayed on the Wallet quick link button) has increased by the retail profit amount.
             [ ] Tap the Wallet button. Verify that the recent transaction list shows a "+ [Amount]" transaction labeled "commission" or "Retail Profit".
             [ ] Verify that the PPV indicator on the Rank status card has increased by the PV of the logged customer sale.

[ ] 16. THEONUTRA V1 COMPENSATION ENGINE + STEP 26 GAPS
================================================================================
Official logic:
  PPV (monthly personal) → GPV (monthly team, exclude self) → Lifetime CGV
  → Star 1–7 upgrade → Active Monthly Bonus + Differential → PV×USD×TZS
  → Staff approve → Wallet credit → Monthly payout batch via confirmed payment number

Retail profit stays OUTSIDE the network engine (cash/reporting — not differential %).

    [ ] Confirm star_ranks seed:
          Star1 PPV≥10 CGV≥0 2% | Star2 20/200 5% | Star3 30/400 9% |
          Star4 30/1000 13% | Star5 40/5000 17% | Star6 40/8000 22% |
          Lead Star7 50/12000 28%
    [ ] GET /api/compensation/star-ranks returns the 7 ranks.
    [ ] GET /api/compensation/me (distributor token) returns:

          ppvNeeded, cgvNeeded, legs.{left,center,right}, currency
    [ ] Labels: lifetimeCgv must NOT reset when calendar month changes

--------------------------------------------------------------------------------
[ ] 16.5. Monthly job: Active + Differential bonuses
    [ ] Preconditions: distributor Active (PPV ≥ current rank min_ppv), has downline
        with their own PPV this period, and higher bonus_percent than downline.
    [ ] Run monthly job.
    [ ] Check network_bonuses:
          [ ] Row bonus_type='active_monthly' for self: bonus_pv ≈ PPV × (rank%/100)
          [ ] Row bonus_type='differential' per downline member where
                (your% − their%) > 0: bonus_pv ≈ downline_PPV × diff%
          [ ] If your% ≤ their%: no differential (0)
          [ ] If INACTIVE (PPV below rank min): no active_monthly and no differential for you
          [ ] amount_tzs = bonus_pv × usd_per_pv × usd_tzs_rate (default 1 × 2500)
          [ ] status = 'pending'
    [ ] Manage -> Network Bonuses lists pending rows with TZS + PV.
